# Xapp mobile app

Expo (SDK 58) + Expo Router app. Routes live in `src/app/`; everything else outside it.

- Install packages with `npx expo install <pkg>` (add `EXPO_OFFLINE=1` if api.expo.dev is unreachable).
- All user-facing text goes through i18next (`src/i18n/locales/{en,fr,ar}.ts`). `en.ts` defines the shape; `fr` and `ar` must match it.
- Arabic is right-to-left. Phones use the native RTL mode: `language-provider.tsx` calls `I18nManager.forceRTL` and restarts the app once (`reloadAppAsync`) when it doesn't match the language; the web sets `dir`. Lay out with `start`/`end` and flex (they follow the language). In native RTL `left`/`right` are swapped, so when something must sit on a physical side use `physical()` from `@/i18n/direction` (the menu drawer, drawings in `motion/scenes.tsx`). Use `Text` (handles alignment; `userText` aligns what a person wrote by its own language), `TextInput` (aligns typed text by its language; always shows a border), and `useLanguage().rtl` for direction-dependent icons. Text is capped at 1.15× the system font size so very large phone text can't push screens off the edges.
- Follow `docs/DESIGN_SYSTEM.md`. Colors come from `useColors()` / `useTheme()` in `src/theme.ts` (palette in `src/lib/palette.ts`, AAA-checked by `src/lib/contrast.test.ts`); don't hardcode hex values in screens. Use `primary` for accent text/icons and `primaryFill`/`successFill`/`accentFill` for filled backgrounds with `onPrimary` text.
- Navigation is the ☰ `MenuButton` / drawer (`components/menu-drawer.tsx`, top start corner, so top-right in Arabic) plus `/history`; there is no tab bar. Building blocks: `Screen` (`header` dissolves on scroll, `footer` pinned on glass, `overlay` for floating parts like `CalloutSlot`), `Card` (opaque + rim), `Button` (`accent` = the one white main action), `BentoGrid/BentoTile`, `Sheet` (draggable bottom sheet), `Glass` (floating parts only), `PressableScale`, `Segmented`. Motion: `Springs` in `lib/motion.ts` with Reanimated (use `.get()/.set()` on shared values for the React Compiler lint). Haptics: `haptic()` in `lib/haptics.ts`; `play(sound)` also triggers the matching haptic.
- The map is never covered: map screens keep it on top (`QuestScreen top`, `Screen top` for the driver load/job and live trip), and sheets over a map use `Sheet overMap` (panel height only, shrinks with the keyboard, no dimming). Pickup/drop-off are pins on a pointer (violet box / red flag, with short labels); the client is a person pin (`FreightMap person`); answers pop onto the request map (`request/answers-on-map.tsx`) and the chosen vehicle drives the route (`traveller`). Live events and next steps show as top notifications (`components/notice.tsx`, swipe to hide); in the background they also go to the phone's notifications. App logo: `assets/brand/mark.svg` → `node scripts/make-logo.js`; animated intro in `motion/intro.tsx`.
- Client home asks "From where?" then "Where to?" (`app/client.tsx` steps). Times are picked on clock/calendar wheels (`components/wheel-picker.tsx`, `request/time-wheels.tsx`; a `tick` sound + haptic per row). Panels and map sheets rise with the keyboard on phones and in the browser (`useKeyboardHeight` in `lib/keyboard.ts`, which reads `visualViewport` on the web). The client's vehicle is a preference: drivers with other vehicles still see and can offer on a request (only a known weight above their capacity blocks it).
- Keep screens simple: one question or one main action per screen, fitting one phone view (see the Simplicity section of `docs/UX_PRINCIPLES.md`). The request flow is `app/request.tsx` + `components/request/questions.tsx` on `QuestScreen`/`ChoiceCard` (`components/motion/quest.tsx`); animations and celebrations are in `components/motion/` (`effects.tsx`: `Shimmer`, `PulseDot`, `Float`, `Pop`, `CountUp`, `Nudge`; `celebration.tsx`: `Celebration`, `useBecameTrue`). Don't add the safe-area insets in screens: the root layout already does. `Screen`, `QuestScreen` and the chat lift their content above the keyboard (`KeyboardAvoidingView` with padding, needed on Android edge to edge).
- Before finishing: `npm run typecheck` and `npx expo export --platform web` must succeed.
- Browser preview: `npx expo export --platform web --output-dir <dir>` then `python3 scripts/build-preview.py <dir> <out.html>` makes one self-contained page (async routes are off in `app.json` so the build is a single bundle). Inside it, `alert()` does nothing, so show messages in the page.
- Live data goes through `src/backend/`: a small `Store` interface (`store.ts`) with two implementations — `shared-store.ts` (the preview page's shared `db`, live across devices) and `local-store.ts` (on-device, live across browser tabs). Screens use `useDoc`/`useQuery` from `@/backend` and the functions in `backend/actions.ts`; a hosted backend (e.g. Supabase) should implement `Store`.
- Maps: `components/map/freight-map.tsx` (MapLibre on phones with free OpenStreetMap vector styles from OpenFreeMap, no API key, plus the phone's location dot) and `freight-map.web.tsx` (Web Mercator; OpenStreetMap/CARTO street tiles, falling back to bundled Natural Earth shapes where tiles are blocked, e.g. the preview). Places and search: `constants/places.ts` over `places-data.ts`, generated by `scripts/build-places.py` from GeoNames + `scripts/data/places-ma.txt`; matching in `lib/place-search.ts` (unit-tested); online addresses in `lib/geocode.ts`; recents in `lib/recent-places.ts`.
- Android test APK: `.github/workflows/android-apk.yml` builds it on GitHub Actions (prebuild + Gradle, release signed with the debug key) on each push to `feature/app-setup` and publishes it as the `latest-apk` pre-release.
- Sounds: `lib/sounds.ts` (`play('tap' | 'send' | 'offer' | ...)`); files generated by `scripts/make-sounds.py`.
- `npm test` runs the pure logic tests (`src/lib/*.test.ts`).
- Trips run themselves from GPS: `lib/trip.ts` (`autoStatus`, reminders, levels, reliability — unit-tested). Drivers act with `SwipeButton` (slide to start / deliver); delivery closes with the client's 4-digit code. Trip events are written into the chat with `postEvent`.
- Booking reminders: in-app via `components/live-events.tsx`, and as phone notifications via `lib/notify.ts` (no-op on web).
- Media (voice notes, HD photos, videos): `lib/media.ts` (`captureMedia`, `storeFile`) and `components/media/` (recorder hook, player, gallery/viewer). In the preview, files go to the page's `assets` store and are referenced as `/_blob/<id>` (the db only keeps the URL; documents are capped at 256 KB). On phones they stay on the device until the hosted backend has file storage. The preview blocks the microphone, so the recorder falls back to choosing an audio file.
- Call / WhatsApp / maps buttons use `ExternalLink` (`components/external-link.tsx`): a real `<a href>` on web (the preview blocks opening links from code), `Linking` on phones.
- Vehicle pictures: `assets/images/vehicles/*.webp`, rendered with Blender by `scripts/render-vehicles.py` and packed by `scripts/pack-vehicles.py`; `vehicleImage(id)` in `constants/vehicles.ts`.
